# DouyinLiveRecorder Web 管理界面部署说明

本增量包把已经完成的 Web 管理界面套用到你现有的 DouyinLiveRecorder 原版源码上，不引入任何第三方 Python 依赖，仍然只需要 `python main.py`。

## 一、增量包内容

```
web-ui-addon/
├── web/                        # 新增：Web 服务端与前端资源
│   ├── __init__.py
│   ├── server.py               # HTTP 服务与路由（标准库 ThreadingHTTPServer）
│   ├── service.py              # 直播间配置、录制设置、日志脱敏、系统信息
│   └── static/
│       ├── index.html
│       ├── app.css
│       └── app.js
├── tests/
│   └── test_web_service.py     # 32 项单元与接口测试
├── patches/
│   ├── main.py.patch           # 必需
│   ├── docker-compose.yaml.patch
│   └── README.md.patch
├── apply_web_ui.py             # 一键套用脚本
└── 部署说明.md
```

## 二、源码部署步骤

1. 先在你自己的仓库里提交一次，保证可回滚：

   ```bash
   git add -A && git commit -m "chore: 套用 Web 管理界面前的基线"
   ```

2. 执行套用脚本（参数是原版源码根目录，需包含 `main.py` 与 `config` 目录）：

   ```bash
   python web-ui-addon/apply_web_ui.py D:/你的路径/DouyinLiveRecorder
   ```

   脚本会：复制 `web/`、`tests/`，并用 `git apply --3way` 打三个补丁。
   因为补丁基于上游 v4.0.7 生成，若你的 `main.py` 已改过导致补丁失败，脚本会提示，按第四节手动合并。

3. 启动程序：

   ```bash
   python main.py
   ```

   终端会打印 `Web 管理界面已启动，请在浏览器中访问 http://127.0.0.1:8080`。

4. 浏览器打开：

   ```
   http://127.0.0.1:8080
   ```

5. 首次运行会自动在 `config/config.ini` 末尾创建 `[Web]` 小节（启用=是、监听 127.0.0.1、端口 8080），无需手动改配置。需要改端口或监听地址时，可用环境变量覆盖：

   | 环境变量 | 说明 | 示例 |
   | --- | --- | --- |
   | `DLR_WEB_ENABLED` | 是否启用 | `true` / `false` |
   | `DLR_WEB_HOST` | 监听地址 | `127.0.0.1` / `0.0.0.0` |
   | `DLR_WEB_PORT` | 端口 | `8080` |

## 三、Docker 部署

补丁已把 `docker-compose.yaml` 改为从当前目录构建镜像（官方镜像不含本次新增的 `web/`），并只把端口映射到宿主机回环地址：

```bash
docker compose up -d --build
```

容器内监听 `0.0.0.0:8080`，宿主机仍只能通过 `http://127.0.0.1:8080` 访问。
若继续使用官方镜像 `ihmily/douyin-live-recorder:latest`，Web 界面不会出现，必须本地构建。

## 四、补丁失败时手动合并 main.py

只有三处改动，按顺序加即可：

1. `read_config_value()`：把逐个补齐 section 的写法改为循环补齐，列表中加入 `'Web'`；缺项时改为调用 `from web.service import upsert_ini_option` 行级写回（不用 `configparser.write` 重写全文，避免破坏注释与 Cookie 段）。

2. 在 `while True:` 之前新增：
   - `get_web_runtime_snapshot()`：返回版本、运行时长、监测数、录制中、错误数等白名单状态；
   - 读取 `[Web]` 配置（支持环境变量覆盖），并以 daemon 线程启动 `start_web_server(...)`，传入 `file_update_lock` 与状态回调。

3. 主循环里 `URL_config.ini` 为空的分支：Web 启用时不再 `input()` 阻塞，改为打印提示后继续循环；Web 关闭时保持原交互行为。

完整实现可参考本工作区已改好的 `DouyinLiveRecorder/main.py`（搜索 `get_web_runtime_snapshot` 与 `Web 管理界面`）。

## 五、Cookie 设置页

侧边栏新增「Cookie 设置」，用于在线维护 `config/config.ini` 的 `[Cookie]` 小节（约 50 个平台）：

- 默认只显示掩码预览（首尾各留少量字符），并展示是否已填写、字符长度
- 点击右上角「载入明文」并经确认后才请求明文（`GET /api/cookies?reveal=1`），此时才可编辑、保存、清空
- 支持按平台名/配置键搜索、只看已填写
- 写入使用行级定点更新：**不会**做 `%` → `%%` 转义，因此 `ttwid=1%7Cxxx` 这类百分号编码不会被写坏；同时保留注释、顺序与其他小节
- 写入前自动备份到 `backup_config`
- 接口只允许修改 `[Cookie]` 小节中已存在的键，写入 `pushplus推送token`、`账号密码`、录制设置等键会返回 400

## 六、验证

```bash
python -m unittest discover -s tests -p "test_*.py"     # 41 项应全部通过
curl http://127.0.0.1:8080/api/health
curl http://127.0.0.1:8080/api/status
curl http://127.0.0.1:8080/api/cookies                  # 只返回掩码
```

## 七、安全边界

- 默认只绑定 `127.0.0.1`，接口校验 `Origin` 与 `Host` 同源，变更接口只接受 `application/json`（限 1MB）。
- 除 Cookie 页面外，不提供、不展示、不允许修改 Authorization、账号密码、推送 token / webhook、代理地址、自定义脚本命令。
- Cookie 明文只在用户主动点击「载入明文」并确认后才返回，页面顶部会给出提醒，保存后重新回到掩码显示。
- 界面没有登录鉴权，请不要直接暴露到公网或不可信网络；确需局域网访问时自行加反向代理与鉴权。
- `config/config.ini` 在仓库里是受版本控制的，若你填写过真实 Cookie / 推送密钥，推送前请确认是否要剔除该文件。
